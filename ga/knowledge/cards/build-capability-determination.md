The planner is only as good as the library, and the library is never finished; so the rule is: when the retrieved
knowledge names a method for this sheet's cues and the ingredients are on this machine (the reference layer, the
reader's cues, numpy and OpenCV), and the library has no primitive for it, the plan names the primitive with a
concrete method and the builder writes it before the batch runs. Known to be buildable in hours to a day, each with
a card that says how: toponym constellation fit, polyline shape matching, render-and-correlate, building-footprint
matching, parcel-boundary matching with acreage check, neighbour-sheet continuity, sheet-index lookup for a new
series, grid-label reading for a new margin style, a datum shift, overlay with chance-level margin, landmark
locate for photographs, a map-text spotter binding, a new learned-matcher binding. Not buildable as a primitive and
to be abstained on with the reason: camera pose from one oblique photograph (needs 3D models), reading text that
is not legible at the scan's resolution (ask for a rescan), placing a sheet with no cue and no record, and
anything that would need the model to output coordinates. The two easy blind inputs that failed before the street-
name matcher existed are the measured case: knowledge of the method was in the literature all along; the system
lacked the determination to build it. Determination is this rule plus the builder.
